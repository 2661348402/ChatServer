# 测试报告

## 1. 测试结论

本报告记录聊天服务器从基础功能验证到群聊高并发优化的主要测试结果。最终版本在 100 人群聊、60 个本机在线用户、20 个远端在线用户、20 个离线用户、32 个发送者、500 QPS、60 秒压测场景下完成：

| 指标 | 结果 |
| --- | ---: |
| 发送群聊消息数 | 30000 |
| 本机转发消息 | 1770000 / 1770000 |
| 缺失消息 | 0 |
| Redis 发布次数 | 600000 |
| Redis 发布失败 | 0 |
| 异步离线落库行数 | 600000 |
| 业务线程池拒绝任务 | 0 |
| 业务队列最大积压 | 8 |
| `groupChat()` 平均处理耗时 | 1067 us |

核心结论：

- 功能链路覆盖注册、登录、私聊、群聊、好友、群组、离线消息、跨节点转发和心跳保活。
- 群聊热路径优化后，100 QPS、8 发送者场景吞吐从 `1675.33 msg/s` 提升到 `5898.99 msg/s`，约提升 `3.5x`。
- 修复业务线程池分片后，500 QPS 场景不再出现业务队列打满和任务拒绝。
- 异步离线消息落库后，500 QPS 下 `avg_group_us` 从约 `5691 us` 降到 `1067 us`，约提升 `5.3x`。
- 500 QPS 高扇出场景下客户端端到端延迟仍偏高，主要受 Python 压测客户端接收、JSON 解析和统计 `1770000` 条本机转发消息影响；服务端指标显示业务处理、Redis 发布和异步离线落库均已完成。

## 4. 分布式与稳定性测试

### 4.1 Redis 跨节点转发

测试步骤：

1. 启动 Redis。
2. 启动 `server1:6001` 和 `server2:6000`。
3. 客户端 A 连接 `6001`，登录用户 101。
4. 客户端 B 连接 `6000`，登录用户 102。
5. A 向 B 发送私聊消息。

结果：B 能收到跨节点消息，说明 Redis Pub/Sub 转发链路通过。

### 4.2 Redis 故障降级

测试步骤：

1. MySQL、Redis、两个 ChatServer 节点正常运行。
2. 用户 A 和用户 B 分别登录不同节点。
3. Redis 正常时，A 给 B 发消息，确认跨节点实时收到。
4. 关闭 Redis。
5. A 再给 B 发消息，服务端不崩溃。
6. 查询 `OfflineMessage` 表，确认消息进入离线消息。
7. 重启 Redis，观察订阅线程重连并恢复订阅。
8. 再次发送跨节点消息，确认 Redis 恢复后可继续发布/订阅。

结果：Redis 故障降级、重连和恢复订阅测试通过。

### 4.3 心跳保活

| 场景 | 操作 | 预期结果 | 结果 |
| --- | --- | --- | --- |
| 正常心跳 | Qt 客户端登录后保持在线 2 分钟以上 | 客户端每 30 秒发送 `PING_MSG`，服务端不误判离线 | 通过 |
| 心跳超时 | 临时停止客户端心跳，保持连接不主动断开 | 服务端 90 到 100 秒后主动关闭连接并更新离线状态 | 通过 |

- Redis publish 队列化，避免群聊 worker 被 Redis 网络 I/O 阻塞。

### 6.6 业务线程池分片修复

问题：原线程池直接使用连接地址 `key % worker_count`，受内存对齐影响，任务集中到少数 worker，500 QPS 下业务队列达到上限。

修复：取模前对 key 做位混合，保持同连接有序，同时让不同连接更均匀分布到多个 worker。

| 修复前 | 8 | 500 | 30000 | 610413 | 1770000 | 1159587 | 15681.77 ms | 25928.24 ms | 19 | 10000 | 8257705 |
| 修复后 | 8 | 100 | 6000 | 354000 | 354000 | 0 | 5.09 ms | 33.40 ms | 0 | 2 | 57 |

| 修复后 | 32 | 500 | 15044 | 887596 | 887596 | 0 | 54.63 ms | 193.26 ms | 0 | 14 | 1163 |

结论：分片修复后，服务端对实际收到的群聊消息都能完成处理，不再出现任务拒绝。此阶段目标 500 QPS 未完全打满，瓶颈转为 Python 压测客户端发送侧。

## 7. 最终版本指标

### 7.1 异步离线落库优化

优化方式：

- `groupChat()` 只收集离线用户和消息内容，并投递到异步离线落库队列。
- 后台线程按时间窗口或行数阈值批量 flush 到 MySQL。
- Redis 发布失败后的降级落库也统一进入异步离线落库队列。
- 服务关闭前 flush 队列中剩余任务。
